# Configuration

<p>Edit <code>config/filament-sanchaya.php</code> after publishing. The storage directory settings control paths generated by Sanchaya; they do not replace Laravel's configured filesystem disk.</p>

```php
return [
    // Eloquent model for file records
    'model' => \DP0\Sanchaya\Models\SanchayaFile::class,

    // Eloquent model for polymorphic attachments
    'attachment_model' => \DP0\Sanchaya\Models\SanchayaAttachment::class,

    // Gate policy for file operations. null = no authorization.
    'policy' => \DP0\Sanchaya\Policies\SanchayaFilePolicy::class,

    // true = soft deletes (recoverable); false = hard delete
    'soft_deletes' => true,

    'allowed_disks' => null,

    'default_disk' => env('SANCHAYA_DEFAULT_DISK', 'public'),

    'storage' => [
        'base_directory' => 'sanchaya',
        'date_format' => 'Y/m',
        'path_generator' => \DP0\Sanchaya\Support\DefaultPathGenerator::class,
    ],

    'file' => [
        'max_file_size'       => 10240,  // KB - 10 MB
        'chunked'             => false,  // Opt in to large-file uploads
        'max_chunked_file_size' => 102400, // KB - 100 MB
        'chunk_size'          => 2048,   // KB - 2 MB per request
        'finalizer'           => \DP0\Sanchaya\Actions\FinalizeChunkedUploadAction::class,
        'chunk_upload' => [
            'register_route' => true,
            'route_name' => 'sanchaya.upload-chunk', // Used when register_route is false
            'uri' => 'sanchaya/upload-chunk',
            'require_signed_url' => true,
            'signed_url_expiration' => 120, // minutes
            'middleware' => ['web', 'throttle:600,1'],
        ],
        'accepted_file_types' => [],     // e.g. ['image/*']
    ],

    'storage_quota' => null, // bytes; null = unlimited

    'actions' => [
        'preview' => [
'enabled' => true,
'label' => 'Preview',
'icon' => 'heroicon-m-eye',
        ],
        'download' => [
'enabled' => true,
'label' => 'Download',
'icon' => 'heroicon-m-arrow-down-tray',
'class' => \DP0\Sanchaya\Actions\DownloadAction::class,
        ],
        'create_folder' => [
'enabled' => true,
'label' => 'Create Folder',
'icon' => 'heroicon-m-folder-plus',
'class' => \DP0\Sanchaya\Actions\CreateFolderAction::class,
        ],
        'rename' => [
'enabled' => true,
'label' => 'Rename',
'icon' => 'heroicon-m-pencil',
'class' => \DP0\Sanchaya\Actions\RenameAction::class,
        ],
        'move' => [
'enabled' => true,
'label' => 'Move',
'icon' => 'heroicon-m-arrow-right-circle',
'class' => \DP0\Sanchaya\Actions\MoveAction::class,
        ],
        'copy' => [
'enabled' => true,
'label' => 'Copy',
'icon' => 'heroicon-m-document-duplicate',
'class' => \DP0\Sanchaya\Actions\CopyAction::class,
        ],
        'delete' => [
'enabled' => true,
'label' => 'Delete',
'icon' => 'heroicon-m-trash',
'class' => \DP0\Sanchaya\Actions\DeleteAction::class,
        ],
    ],

    'sanchaya_picker' => [
        'multiple' => false,
        'allowed_types' => [], // e.g. ['image']
        'max_files' => null,
    ],
];
```

<h3>Storage path behavior</h3>
<p>New uploads use the configured base directory followed by the configured date format. With the defaults, a file is stored under a path similar to <code>sanchaya/2026/10/{uuid}.jpg</code>. Existing database paths are not rewritten when these settings change.</p>
<p>The <code>storage.base_directory</code> value is a relative namespace on the selected disk. It is independent from <code>default_disk</code> and from the Laravel filesystem root. For example, changing the base directory to <code>media</code> changes generated paths to <code>media/2026/10/{uuid}.jpg</code>, while the disk remains the selected disk.</p>

<h3>Chunked upload settings</h3>
<p>Chunked uploads are disabled by default. Enable them globally to show the large-file mode in both the standalone manager and picker:</p>

```php
'file' => [
    'chunked' => true,
    'max_chunked_file_size' => 102400, // KB per file
    'chunk_size' => 2048, // KB per request
],
```

<p>The chunk size must fit within the server's PHP and web-server request limits. Chunks are staged in <code>storage/app/sanchaya-chunks</code>, assembled, then streamed to the selected disk. Multi-server deployments need shared staging storage or request affinity while an upload is in progress.</p>

<h3>Override the chunk finalizer</h3>
<p>Replace the default finalizer when your application needs custom validation, storage, metadata, or record creation:</p>

```php
'file' => [
    'finalizer' => \App\Actions\FinalizeMediaUploadAction::class,
],
```

<p>The custom class must implement <code>DP0\Sanchaya\Contracts\ChunkUploadFinalizer</code>. See <a href="/v1.1.0/chunked-uploads#customize-finalization">Customize finalization</a> for the method contract and lifecycle.</p>
